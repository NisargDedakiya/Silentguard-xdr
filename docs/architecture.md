## Backend layering

```
routers/        HTTP endpoints (thin) — auth, agents, admin, detections, intel,
                responses, analytics, integrations, policies, users
services/       business logic — auth, tenancy, events, policy, response,
                threat_intel, analytics, integrations, inventory, email
detection/      rule engine + rule packs
core/           config, logging, middleware, errors, security, roles,
                permissions, ssrf
models.py       SQLAlchemy ORM (17 tables) · migrations/  Alembic
```

Requests flow: **middleware → router (authz via `require_permission`) →
service → ORM**. Cross-cutting concerns (config, logging, tenancy scoping,
auditing) live in `core/` and `services/` so they are reused across REST, the
WebSocket hub, and the background monitor.
